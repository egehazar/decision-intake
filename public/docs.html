DecisionIntakescreener · walkthrough · openapi.json · source

Developer guide

DecisionIntake decides what to ask next in a US benefits screening, how far to trust each answer, and when it knows enough to recommend programs or should suggest a person review the case. Your product keeps the conversation; the engine keeps the decision. Engine 1.0.0 at https://decision-intake.vercel.app; every example below is a real response, generated from the code by experiments/build_docs.py.

1. The loop

One endpoint does the work. Send what you know, get back the next step, repeat until the step is finish or hand_off. The service keeps nothing between calls: every response carries a state string, and you send it back with the next call. No key, no account.

CallBodyReturns
POST /v1/step{"state"?, "facts"?}the new state, how each fact was read, and next: ask, finish or hand_off
POST /v1/assessment{"state"}every program's probability, tier and yearly value range; the facts so far; how well the data covers this household
GET /v1/questions-the ten programs and all 18 questions with their options
POST /mcpJSON-RPCthe same engine as tools for AI assistants (section 5)
GET /healthz-liveness, version, and the commit and model and rules hashes deployed

2. Facts and readings

Record anything the person said, asked or not. Each fact is exactly one of three kinds:

KindExampleNotes
choice{"question": "children", "choice": "2"}the option's text; numbers map onto ranges like "4 or more"; true/false onto yes/no; on amount questions a range's text works too
amount{"question": "earned_income", "amount": {"value": 2400, "period": "month", "approximate": true}}as said: a value or low/high, a period (year, month, week, none). Don't convert it yourself: the engine does the arithmetic and spreads approximate amounts over neighbouring ranges
don't know{"question": "assets", "dont_know": true}no evidence; the belief is unchanged

Corrections, rejected facts and warnings

A fact for an answered question replaces it (replaces shows the old reading). A fact that can't be read is not recorded, its reading has an error saying how to fix it, and the other facts in the call still go in. A warning means no household on record fits this answer together with the others: check it with the person.

3. Responses

When no remaining question is worth asking, next.action is finish, or hand_off when the doubt left is still costly enough that a person should go through it.

FieldMeaning
recommendprograms worth applying for; tier is likely (probability at least 0.5) or worth checking (applying is worth it in expectation, but less likely than not); value_if_eligible_per_year is [low, high] in whole dollars (health coverage: its value, not cash)

progress.expected_mistake_costdollars a year the remaining doubt is expected to cost
notewhat this is and isn't; show it with every result

4. The state string

The facts so far, readable, with a checksum so a mangled copy is refused instead of misread:

di1;children=2;state=TX;earned_income=~2400/month;household_size=3;infant_or_pregnant=no;married=no;child_under5=no;social_security=none;#4aa1

Choices are option text (spaces as _), amounts are ~-prefixed when approximate with .. for ranges and /period, don't-know is ?, and # ends with four hex digits of a CRC-32 (a 16-bit check). It is not encrypted or signed: it holds what the person said, so treat it like the answers themselves. Send it in POST bodies, never in URLs, and don't log it. The service doesn't: its logs hold route, status and timing only. A damaged state is refused:

{
  "error": {
    "code": "bad_state",
    "message": "state is damaged (its check doesn't match); pass the exact state string from the most recent result"
  }
}

5. AI assistants (MCP)

The same engine speaks the Model Context Protocol over Streamable HTTP at https://decision-intake.vercel.app/mcp: the stateless 2026-07-28 revision, and the handshake revisions 2025-11-25, 2025-06-18 and 2025-03-26. JSON responses, no SSE stream, no sessions. The assistant does the talking and turns the person's words into facts; the engine decides what to ask and when to stop. In a registered test on 200 simulated households, Claude Haiku made 41% fewer costly mistakes with these tools than without them (unweighted; the model card has the caveats).

Claude Code

claude mcp add --transport http decisionintake https://decision-intake.vercel.app/mcp

Claude.ai and other clients

Add a custom connector with the URL https://decision-intake.vercel.app/mcp. The server's instructions tell the assistant how to run an intake. Tools (all read-only: each is a pure function of its arguments):

  • start_intake (Start a benefits screening): Open a new benefits-screening intake. Returns the first `state` (pass it to every later call), the ten programmes, every question the engine can use (ids, options, amount units), and the first step.
  • record_facts (Record what the person said): Record what the person said as typed facts (any questions, asked or volunteered; a fact for an answered question replaces it). Returns how each fact was read and the next step. Returns the new `state`; use it from now on. With an empty facts list it only returns the next step.
  • get_assessment (Current assessment): The current assessment: every programme's probability, tier and yearly value range, the facts recorded so far, and the expected cost of mistakes. A screening estimate, not an eligibility decision.

6. Code

JavaScript

const BASE = "https://decision-intake.vercel.app";
async function step(state, facts) {
  const r = await fetch(BASE + "/v1/step", {
    method: "POST", headers: {"Content-Type": "application/json"},
    body: JSON.stringify({state, facts})
  });
  if (!r.ok) throw new Error((await r.json()).error.message);
  return r.json();
}

// askThePerson, explain and showResults are your UI (placeholders)
let {state, next} = await step(undefined, []);           // start
while (next.action === "ask") {
  const fact = await askThePerson(next.question, next.why); // a choice, an amount as said, or don't know
  const r = await step(state, [fact]);
  const problem = r.readings.find(x => x.error);
  if (problem) explain(problem.error);                    // not recorded: the same question comes back
  ({state, next} = r);
}
showResults(next);   // recommend, unsure, note; next.action === "hand_off" adds hand_off_reason

Python, standard library only

import json, urllib.request

BASE = "https://decision-intake.vercel.app"

def step(state=None, facts=()):
    req = urllib.request.Request(BASE + "/v1/step", method="POST",
        data=json.dumps({"state": state, "facts": list(facts)}).encode(),
        headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req) as r:
        return json.load(r)

7. Integration checklist

  • Show the note with every result, and say the tool is not a government site and not an application.
  • Never present "doesn't look likely" or "can't tell" as a denial. Offer the official way to apply for every program, including those.
  • Present values as rough yearly ranges if eligible, never as an amount the person will receive.
  • Treat hand_off as advice to talk to a navigator (211 is free); it does not refer anyone.
  • Keep state out of URLs, analytics and logs; it is the person's answers.
  • Ask about the household as the questions word it; the engine does not ask about immigration status, which can change eligibility.

8. Errors, limits and versions

Errors are JSON: {"error": {"code", "message"}}. A fact that can't be read doesn't fail the call (section 2).

StatusWhen
200success; MCP protocol errors are JSON-RPC errors in a 200 for the handshake revisions
202MCP notification accepted
400bad_json, bad_request, bad_state (damaged state, or one written for another question set); MCP 2026-07-28 errors
403MCP only: a browser Origin this server doesn't accept
404, 405no such route; wrong method (MCP is POST only)
413, 415body over 64 KB; not application/json
429more than 120 requests a minute from one IP address to /v1/* or /mcp; wait a minute
500internal; nothing about the failure is returned, the server log keeps it
LimitValue
Request body64 KB
Facts in one call40
State string2,000 characters
Amountsnumbers from 0 to 1,000,000,000
Rate120 requests a minute per IP address on /v1/* and /mcp (a whole screening is about 10)
Latencyabout 300 ms of server time a step; the first call after a quiet spell adds about a second

Cross-origin use. The JSON API answers any origin (no credentials are involved). /mcp serves clients that send no Origin (server-side assistants and tools) and browsers from this site or localhost; ask in the repository if a browser client elsewhere needs it.

Versions. The engine is 1.0.0; /healthz reports it with the commit and the model and rules hashes. A state stays readable across deployments while the questions and their options are unchanged. A release that changes them makes older states bad_state: start again (the public screener does this for you). Breaking changes to the API move the major version. This is a free research service with no uptime guarantee; it is monitored every 30 minutes.
