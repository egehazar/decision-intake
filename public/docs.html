Quick Benefits Checkopenapi.json · source

Developer guide

DecisionIntake decides what to ask next in a US benefits screening, how far to trust each answer, and when it knows enough to recommend programmes or should hand the case to a person. Your product keeps the conversation; the engine keeps the decision. Engine 1.0.0; every example below is a real response from this service.

1. The loop

One endpoint does the work. Send what you know, get back the next step, repeat until the step is finish or hand_off. The service keeps nothing between calls: every response carries a state string, and you send it back with the next call.

CallBodyReturns
POST /v1/step{"state"?, "facts"?}the new state, how each fact was read, and next: ask, finish or hand_off
POST /v1/assessment{"state"}every programme's probability, tier and yearly value range; the facts so far; how well the data covers this household
GET /v1/questions-the ten programmes and all 18 questions with their options
POST /mcpJSON-RPCthe same engine as tools for AI assistants

2. Facts

Record anything the person said, asked or not: a fact for a question that already has one replaces it (a correction). Three kinds:

KindExampleNotes
choice{"question": "children", "choice": "2"}the option's text; numbers map onto ranges like "4 or more"; true/false onto yes/no
amount{"question": "earned_income", "amount": {"value": 2400, "period": "month", "approximate": true}}as said: a value or low/high, a period (year, month, week, none); the engine does the arithmetic and spreads approximate amounts over neighbouring ranges
don't know{"question": "assets", "dont_know": true}no evidence; the belief is unchanged

FieldMeaning

A screening estimate from PolicyEngine-US's 2026 rules, not an eligibility decision. Always offer the official way to apply, including for programmes that don't look likely. The model card says where it is wrong.

4. The state string

The facts so far, readable, with a check so a mangled copy is refused instead of misread:

di1;children=2;state=TX;earned_income=~2400/month;household_size=3;infant_or_pregnant=no;married=no;child_under5=no;social_security=none;#4aa1

Choices are option text (spaces as _), amounts are ~-prefixed when approximate with .. for ranges and /period, don't-know is ?, and # ends with four hex digits of a CRC. It is not encrypted or signed: it holds what the person said, so treat it like the answers themselves. Send it in POST bodies, never in URLs, and don't log it. The service doesn't: its logs hold route, status and timing only.

5. AI assistants (MCP)

The same engine speaks the Model Context Protocol over Streamable HTTP at {BASE}/mcp (the stateless 2026-07-28 revision, and 2025-11-25 back to 2024-11-05 for clients that still use the handshake). The assistant does the talking and turns the person's words into facts; the engine decides what to ask and when to stop. In a registered test, Claude made 41% fewer costly mistakes with these tools than without them.

Claude Code

claude mcp add --transport http decisionintake {BASE}/mcp

Claude.ai and other clients

Add a custom connector with the URL {BASE}/mcp. Tools:

  • start_intake: Open a new benefits-screening intake. Returns the first `state` (pass it to every later call), the ten programmes, every question the engine can use (ids, options, amount units), and the first step.
  • record_facts: Record what the person said as typed facts (any questions, asked or volunteered; a fact for an answered question replaces it). Returns how each fact was read and the next step. Returns the new `state`; use it from now on. With an empty facts list it only returns the next step.
  • get_assessment: The current assessment: every programme's probability, tier and yearly value range, the facts recorded so far, and the expected cost of mistakes.

6. Code

JavaScript

const BASE = "{BASE}";
async function step(state, facts) {
  const r = await fetch(BASE + "/v1/step", {
    method: "POST", headers: {"Content-Type": "application/json"},
    body: JSON.stringify({state, facts})
  });
  if (!r.ok) throw new Error((await r.json()).error.message);
  return r.json();
}

let {state, next} = await step(undefined, []);        // start
while (next.action === "ask") {
  const answer = await askThePerson(next.question);  // your UI: a choice, an amount, or "don't know"
  ({state, next} = await step(state, [answer]));
}
show(next.recommend, next.unsure, next.action === "hand_off");

Python, standard library only

import json, urllib.request

BASE = "{BASE}"

def step(state=None, facts=()):
    req = urllib.request.Request(BASE + "/v1/step", method="POST",
        data=json.dumps({"state": state, "facts": list(facts)}).encode(),
        headers={"Content-Type": "application/json"})
    with urllib.request.urlopen(req) as r:
        return json.load(r)

r = step(facts=[{"question": "state", "choice": "TX"},
                {"question": "earned_income", "amount": {"value": 2400, "period": "month"}}])
print(r["next"]["action"], r["next"].get("question", {}).get("id"))

7. Errors and limits

Errors are JSON: {"error": {"code", "message"}}. A fact that can't be read doesn't fail the call: its reading carries an error saying how to fix it, and valid facts in the same call still go in.

{
  "error": {
    "code": "bad_state",
    "message": "state is damaged (its check doesn't match); pass the exact state string from the most recent result"
  }
}
